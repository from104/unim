# UNIM 한자 사용자 사전 설계서 (HANJA_USERDICT_SPEC)

> 내장 한자 사전(libhangul `hanja.txt`)에 없는 **이름·기관명·전문용어**를 사용자가 직접
> `한글 → 한자(+뜻)` 로 등록해, 내장 단어와 **똑같이** 모든 한자 변환 대상(단음절·①·②·③)에서
> 후보로 쓰게 한다. 예: `서기현 → 徐基鉉`.
>
> - 상태: **초안 v1.0 (2026-11-16) — 기현님 승인 대기.** 0.4.5 에 싣는다(릴리스 보류 중).
> - 짝 문서: 구현 계획 [`docs/dev/architecture/hanja-userdict-plan.md`](../architecture/hanja-userdict-plan.md)
> - 지키는 규격: [`HANJA_WORD_SPEC.md`](HANJA_WORD_SPEC.md)(대상 규칙·§2.8 로그), [`POPUP_SPEC.md`](POPUP_SPEC.md)(**무변경** — 팝업 모양·키·시그니처 그대로)
> - 본보기: AutoTypeFix 역방향 사용자 사전(`src/typefix_userdict.rs`) — 파일·경로·CLI·설정 페이지 패턴을 그대로 따르되, 아래 §8 의 데이터 보호 규칙은 더 엄격하게 한다.

## 0. 결정 요약

| # | 결정 | 근거 |
|---|---|---|
| D1 | 파일 `<config_dir>/unim/hanja-userdict.yaml`, YAML, `version: 1` | ATF 사전과 같은 위치·형식(`paths::config_dir()` — Windows `%APPDATA%\unim\`, TSF 샌드박스는 `UNIM_CONFIG_DIR` 로 자동 해결) |
| D2 | 사용자 층은 **코어(`src/hanja/user_dict.rs`)의 프로세스 전역 캐시**로 두고, 엔진이 **한자키를 누를 때마다 1회 `stat`** 해 바뀌었으면 다시 읽는다 | 데몬·TSF·IMM32·capi 가 모두 `InputEngine` 을 쓰므로 호스트별 배선 0. ATF 처럼 데몬 워커가 들고 있으면 TSF 를 따로 배선해야 한다. 한자키는 드물어 throttle 불필요 → "다음 한자키부터 적용" 이 정확히 성립 |
| D3 | 내장 사전(`OnceLock<Arc<HanjaDictionary>>`)은 **그대로 불변·공유**. 조회는 엔진 헬퍼 `hanja_search`/`hanja_contains` 가 두 층을 합친다 | 메모리(내장 ~100MB) 재파싱 없음 |
| D4 | 후보 순서 = **즐겨찾기(기존 stable sort) → 사용자 항목(파일 순) → 내장(사전 순)**. 같은 한자는 1번만, 사용자 위치에 | 등록 의도 존중. 즐겨찾기 동작 무변경 |
| D5 | 데몬 D-Bus·config 키 **추가 없음** | CLI·설정앱은 파일을 직접 고치고 엔진이 mtime 으로 감지(ATF 와 같음). 빈 파일 = 꺼짐이라 토글 불필요 → Config 3지점 싱크 대상 아님 |
| D6 | CLI 는 기존 사전 그룹에 맞춰 **`unim-cli dict hanja …`** | `dict user-dict`·`dict blacklist` 와 같은 자리 |
| D7 | 설정 페이지: **GTK(`unim-settings-gtk`)·Slint(`unim-settings`, Linux+Windows)** 두 곳 | Win32 대체 대화상자(`unim-tsf/src/settings_dialog.rs`)는 `unim-settings.exe` 가 없을 때만 뜨는 폴백이라 제외. GNOME 확장 prefs 는 단축키 전용이라 제외 |
| D8 | 읽을 수 없는 파일은 **절대 덮어쓰지 않는다** | 정보 유실 방지(ATF 로더는 파싱 실패 시 빈 사전으로 돌아가 다음 저장에서 원본을 지운다 — 같은 실수 금지) |
| D9 | 자동 학습 없음. 내장 사전과 같은 `(한글, 한자)` 도 등록 허용(맨 앞으로 + 뜻 덮어쓰기 효과) | 내장 사전은 버전마다 바뀌므로 검증을 내장 사전에 묶지 않는다. 설정앱이 100MB 내장 사전을 띄우지 않아도 된다 |

## 1. 데이터 형식·경로

```yaml
# ~/.config/unim/hanja-userdict.yaml   (Windows: %APPDATA%\unim\hanja-userdict.yaml)
version: 1
entries:
  - hangul: 서기현
    hanja: 徐基鉉
    meaning: 내 이름               # 선택 — 없으면 키 생략
    added_at: 1763251200          # Unix 초
  - hangul: 다온
    hanja: 多온                    # ✘ 무효 예(한글 섞임) — 보존되지만 조회에서 빠진다(§8)
```

| 항목 | 규칙 |
|---|---|
| 경로 | `HanjaUserDict::default_path()` = `crate::paths::config_dir()/unim/hanja-userdict.yaml` (Linux `~/.config/unim/`, Windows `%APPDATA%\unim\`). 디렉터리가 없으면 첫 저장에서 만든다 |
| 저장 | `crate::atomic_io::atomic_write`(임시 파일 + rename, 심볼릭 링크 대상 추적) |
| 순서 | `entries` 의 순서 = 같은 한글 안의 후보 순서. 수정은 위치·`added_at` 을 유지한다 |
| 다중 | 한 한글에 한자 여러 개 허용. **`(hangul, hanja)` 쌍이 유일**해야 한다 |
| 버전 | `version` 이 없으면 1. **1 보다 크면 엔진은 읽되(최선), CLI·설정앱은 쓰지 않는다**(모르는 필드 유실 방지) |
| 정규화 | 앞뒤 공백만 제거. **유니코드 정규화(NFC 등) 금지** — 호환 한자(U+F900–FAFF, 예: 不 U+F967)가 통합 한자로 바뀌어 독음 구분이 사라진다 |

## 2. 검증 (추가·수정 시. 읽을 때도 같은 함수로 유효성 판정)

| 대상 | 규칙 | 오류 코드(`EntryError`) |
|---|---|---|
| 한글 | 비어 있지 않음 | `HangulEmpty` |
| | 모든 글자가 **완성 음절 U+AC00–D7A3**(자모·공백·숫자·영문 불가) | `HangulNotSyllable{ch, pos}` |
| | 1 ≤ 글자 수 ≤ **18**(`HANJA_MAX_KEY_CHARS`, 대상①②③ 상한과 동일) | `HangulTooLong{len}` |
| 한자 | 글자 수 = 한글 글자 수(1:1 — 글자별 뜻 합성 `display_meaning` 이 이 전제로 동작) | `HanjaLenMismatch{hangul, hanja}` |
| | 모든 글자가 CJK 표의문자: U+3400–4DBF(확장 A), U+4E00–9FFF, U+F900–FAFF(호환), U+20000–2A6DF(B), U+2A700–2EE5F(C–F·I), U+2F800–2FA1F(호환 보충), U+30000–323AF(G·H). 부수(U+2E80–2FDF)·〇·々 는 불가 | `HanjaNotHan{ch, pos}` |
| 뜻 | 선택. 앞뒤 공백 제거 후 비면 "없음" | — |
| | ≤ **60자**, 제어 문자(줄바꿈·탭 포함) 불가. `:` 등 일반 문장부호는 허용(YAML 이 인용 처리) | `MeaningTooLong{len}`, `MeaningControl` |
| 쌍 | `(hangul, hanja)` 중복 불가(수정 시 자기 자신 제외) | `Duplicate` |

## 3. 조회·병합 규칙

### 3.1 합친 조회 (엔진 헬퍼)

- `hanja_contains(key)` = 사용자 층에 유효 항목이 있거나 `|| 내장.contains(key)`.
- `hanja_search(key)` = `merge_candidates(사용자[key], 내장.search(key))`:
  1. 사용자 항목(파일 순, 유효한 것만).
  2. 내장 항목 중 **한자가 1 에 없는 것**(사전 순).
  3. 1 의 항목이 내장과 같은 한자면 뜻 = 사용자 뜻, 없으면 **내장 원본 뜻**. 둘 다 없으면 빈 뜻 → 팝업 표시 때 기존 `display_meaning` 이 글자별 뜻을 합성(`성씨 서 · 터 기 · 솥귀 현` 식, HANJA_WORD_SPEC §2.5.3 그대로).
- 그 뒤 기존 즐겨찾기 stable sort(`open_hanja_popup`·`toggle_hanja_bookmark`)가 그대로 적용된다 → 최종 **즐겨찾기 → 사용자 → 내장**.
- 즐겨찾기 키는 기존대로 `(target, 한자)` — 사용자 항목도 ★ 가능. 항목을 지워도 즐겨찾기 기록은 남긴다(무해, 다시 등록하면 ★ 복원).
- 팝업에 "사용자 항목" 표시(색·기호)는 **넣지 않는다**(POPUP_SPEC 무변경).

### 3.2 대상별 적용 (내장 단어가 들어가는 모든 자리에 똑같이)

| 대상 | 판정 지점 | 사용자 단어의 효과 |
|---|---|---|
| 단음절(종전) | preedit 마지막 음절 → `hanja_search` | 1음절 사용자 항목이 그 음절 후보 맨 앞(즐겨찾기 다음)에 |
| ① 방금 입력한 어절(음절·단어 모드) | 접미 18→2자 `hanja_contains` 최장 일치 | `서기`+`현` → target `서기현`. 접두 검증(§2.2.3)·교체 능력 게이트는 그대로 |
| ① 팝업 중 한자키 재타(축소) | 더 짧은 접미 `hanja_contains`/`hanja_search` | 사용자 단어도 축소 경유지가 된다 |
| ② 선택 영역 | 공백 제외 정확 일치 `hanja_contains` | 사용자 단어만으로도 대상② 성립 |
| ③ 커서가 걸친 단어 | 후보 집합 `hanja_contains`, 순서 규칙(길이↓·등급·시작) **무변경** | 사용자 단어가 같은 규칙으로 섞인다(가산점 없음) |
| ③ 재타(다음 후보) | `hanja_search` | 동일 |
| 즐겨찾기 토글 재정렬 | `hanja_search` 로 다시 받음 | **사용자 항목이 사라지지 않아야 한다**(회귀 위험 지점) |
| 초성 특수문자 폴백 | 무관 | 사용자 키는 완성 음절뿐이라 겹치지 않음 |

사용자 파일이 없거나 비면 모든 경로가 **종전과 바이트 동일**하다.

### 3.3 스냅샷 일관성

엔진은 사용자 층을 `Arc<HanjaUserIndex>` 스냅샷으로 들고, **새 팝업을 여는 한자키(`start_hanja_conversion` 의 비-한자모드 분기)에서만** 갱신한다. 팝업이 열린 동안(축소·다음 후보·★ 토글)은 같은 스냅샷을 쓴다 — 중간에 파일이 바뀌어도 후보가 흔들리지 않는다.

## 4. 다시 읽기(핫 리로드)

- 갱신 시점: 위 §3.3 의 한자키마다 **`stat` 1회**(throttle 없음). 서명 `(mtime, 길이)` 가 직전과 다르면 다시 파싱해 인덱스를 새로 만들고 `Arc` 를 바꾼다.
- 파일 없음 → 빈 층(지운 즉시 반영. ATF 처럼 옛 내용을 붙들지 않는다).
- 파싱 실패 → 빈 층 + 경고 로그(같은 서명에 1회). 엔진은 **절대 쓰지 않는다**.
- 데몬 재시작·D-Bus 호출 불필요. CLI·설정앱 저장 → 다음 한자키부터 적용. Windows 는 TSF 가 앱 프로세스마다 같은 규칙으로 감지.
- 설정앱의 목록은 2초 mtime 폴링으로 CLI 변경을 반영(ATF 페이지와 같음).

## 5. CLI — `unim-cli dict hanja`

| 명령 | 동작 |
|---|---|
| `list [<한글>]` | 전체(또는 그 한글만) 출력. 무효 항목은 `⚠ 이유` 표시 |
| `add <한글> <한자> [--meaning <뜻>]` | 검증 후 추가 |
| `edit <한글> <한자> [--hangul <새 한글>] [--hanja <새 한자>] [--meaning <뜻>]` | 그 쌍을 찾아 고친다. `--meaning ""` 은 뜻 지움. 옵션이 하나도 없으면 오류 |
| `remove <한글> [<한자>] [-y]` | 쌍 하나 제거. 한자를 생략하면 그 한글의 전부 — **2개 이상이면 확인**(기존 `confirm_multi_removal` 재사용, 비대화형은 `-y` 필수) |
| `clear` | 확인 후 전부 삭제. 파일이 깨져 있으면 "보관 후 비우기"(§8) |
| `path` | 파일 경로 한 줄 |

- 파일 직접 R/W(데몬 경유 아님), 쓰기마다 **디스크에서 다시 읽고 → 고치고 → 원자적 저장**.
- 종료 코드: 성공 0, 하나라도 실패 1. `dict` 서브커맨드 없음 안내(`dict_no_subcommand_hint`)에 `hanja` 추가.
- 메시지(ko 기준, en 짝 필수 — `unim-cli/locales/{ko,en}.yml`, 키 접두 `hanja_dict_*`, 도움말 `help_hd_*`):

| 상황 | 메시지 |
|---|---|
| 추가 | `'서기현 → 徐基鉉'을(를) 한자 사전에 추가했습니다.` |
| 중복 | `'서기현 → 徐基鉉'은(는) 이미 등록돼 있습니다.` |
| 한글 오류 | `한글 '…': 완성형 한글 1~18자만 쓸 수 있습니다. ('ㄱ'은 완성 음절이 아님)` |
| 글자 수 | `한자 '…'는 2자입니다 — 한글(3자)과 글자 수가 같아야 합니다.` |
| 비한자 | `한자 '…'의 3번째 글자 'A'(U+0041)는 한자가 아닙니다.` |
| 뜻 | `뜻은 60자 이하, 줄바꿈 없이 써 주세요.` |
| 없음 | `'서기현 → 徐基鉉'은(는) 사전에 없습니다.` |
| 수정 | `'서기현 → 徐基鉉'을(를) 고쳤습니다.` / 옵션 없음: `바꿀 항목(--hangul/--hanja/--meaning)을 하나 이상 지정하세요.` |
| 파일 깨짐 | `사전 파일을 읽을 수 없습니다(12행 5열): <경로>\n파일을 고치거나 'unim-cli dict hanja clear' 로 보관 후 비우세요.` |
| 새 버전 | `더 새 UNIM 이 만든 파일(version N)이라 수정하지 않습니다.` |
| 목록 | `한자 사용자 사전 (N개):` + `  1. 서기현  徐基鉉  — 뜻` |

## 6. 설정 UI

공통: 페이지 이름 **"한자 사용자 사전"**(en "Hanja User Dictionary", §10-2), ATF "억제 단어"·"사용자 사전" 페이지 바로 뒤. 쓰기마다 디스크에서 다시 읽고, 행 조작은 **인덱스가 아닌 `(한글, 한자)` 로 찾아서** 한다(목록 표시 뒤 CLI 가 파일을 바꿔도 엉뚱한 항목을 지우지 않게).

접근성(입에 젓가락·발 마우스 — 입력·클릭 최소화):
- 추가 대화상자/폼은 **한글 칸에 자동 포커스**, 한글 칸 Enter → 한자 칸, 한자·뜻 칸 Enter → 유효하면 바로 저장. 키보드만으로 `타이핑 → Enter → 타이핑 → Enter`.
- 검증은 **입력 중 실시간**, 오류 이유를 칸 아래에 문장으로(토스트만으로 끝내지 않음). 무효면 저장 버튼 비활성.
- 한자 칸 안내: "한글을 쓰고 한자키로 한 글자씩 바꿔 넣으세요 (예: 서 → 徐)".
- 삭제는 **확인 없이 1클릭 + 5초 '되돌리기'**. 삭제 뒤 스크롤 위치 유지, 포커스는 같은 자리(마지막이면 앞) 행으로.
- 행 전체 클릭 = 편집(작은 아이콘을 노리지 않아도 됨).

| 앱 | 구성 |
|---|---|
| GTK `unim-settings-gtk` | `adw::PreferencesPage` + 그룹(설명에 개수) + 헤더 `+` 버튼. 행 = `adw::ActionRow`(activatable) 제목 `서기현 → 徐基鉉`, 부제 = 뜻(없으면 "뜻: 글자별 자동") 또는 `⚠ 무효: 이유`. 접미 휴지통. 편집 = 모달 `adw::Window` + `EntryRow` 3개 + 오류 라벨. 되돌리기 = `adw::Toast` 버튼 |
| Slint `unim-settings`(Linux·Windows 공용) | 사이드바 6번째 항목(페이지 5, 키보드 탐색 상한 4→5). 카드① 입력 폼(한글·한자·뜻 `LineEdit` + [추가] [고친 내용 저장]) — 목록에서 고르면 폼에 채워지고 저장이 활성. 카드② `StandardListView` + [선택 삭제] → 기존 I6 되돌리기 토스트(`DeleteSnapshot` 에 변형 추가). 2초 `slint::Timer` mtime 폴링 |

## 7. 로그·개인정보 (HANJA_WORD_SPEC §2.8 준수)

- 한글·한자·뜻 **평문을 로그에 남기지 않는다** — 개수·길이만.
  - 리로드: `사용자 한자 사전 로드: 유효 N개, 무효 M개`
  - 파싱 실패: `사용자 한자 사전 파싱 실패(line L col C) — 내장 사전만 사용` — **serde_yaml 오류 문장은 로그 금지**(`invalid type: string "서기현"…` 처럼 내용이 섞인다). 위치만.
  - 후보 로그(기존 `한자 후보 발견: N자 -> M 개`)에 `사용자 K개` 수치만 덧붙인다.
  - 설정앱·CLI 의 `unim_log!` 도 같은 규칙. CLI 가 **사용자 터미널에 출력**하는 결과·오류 문장은 로그가 아니므로 평문 허용.
- 비밀번호 필드: 기존 게이트(`should_block_hangul`)가 대상 결정 전에 막으므로 추가 조치 없음.
