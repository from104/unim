# 5편: 시스템 심부로의 침투 - DBus와 XIM의 벽을 넘다

튼튼한 엔진과 아름다운 UI를 갖춘 `unim`. 하지만 입력기라는 존재는 홀로 빛날 수 없습니다. 메모장, 웹 브라우저, 터미널... 시스템 곳곳에 퍼져 있는 수많은 애플리케이션과 끊임없이 대화해야 하기 때문이죠.

2026년 1월 25일, `unim`은 시스템의 가장 깊숙한 혈관으로 침투하는 대공사를 단행합니다.

```text
f944e15 | 2026-01-25 | feat: migrate to DBus-based IPC architecture
```

## 가로막힌 벽: 동기화되지 않는 대화들

초창기 `unim`은 각 프레임워크(GTK, Qt 등)가 개별적으로 엔진을 호출하는 방식이었습니다. 그러다 보니 브라우저에서 치던 설정이 터미널에서는 적용되지 않거나, 입력기 상태가 꼬이는 일이 발생하곤 했죠.

진정한 '보편적인 입력기'가 되려면, 시스템 전체를 하나로 묶는 강력한 통신망이 필요했습니다. 리눅스 데스크탑의 표준 통신 규약인 **DBus**를 도입하기로 한 것이죠.

## 에이전트와 함께 걷는 통신 프로토콜의 미로

하지만 DBus 전환은 생각보다 훨씬 더 깊은 늪이었습니다. 수많은 메서드 호출, 시그널 전달, 그리고 그 이면에 숨겨진 비동기 처리의 복잡성... 젓가락 타이핑을 하는 저에게 이 방대한 통신 규약을 일일이 설계하고 검증하는 건 거대한 벽이었습니다.

이때 **Antigravity(에이전트 모드)**의 논리 분석력이 빛을 발했습니다.

> "Antigravity, 모든 입력기 모듈이 하나의 대몬과 대화할 수 있는 DBus 인터페이스를 설계해줘. 경합 조건(Race Condition)이 생기지 않도록 아주 정교해야 해."

에이전트는 순식간에 시스템의 통신 구조를 분석하고, 실시간으로 각 모듈 간의 대화 시나리오를 그려냈습니다. 제가 바이브로 던진 "끊김 없는 동기화"라는 추상적인 목표를, 에이전트는 단단한 IPC(기능 간 통신) 레이어로 구체화해낸 것이죠.

## 고대의 유물, XIM을 깨우다

DBus만으로 모든 게 해결되지는 않았습니다. 리눅스 생태계에는 여전히 **XIM(X Input Method)**이라는 '고대의 유물'이 살아남아 있었습니다. 최신 라이브러리를 쓰지 않는 오래된 앱들은 오직 XIM하고만 대화하거든요.

XIM 프로토콜은 악명이 높습니다. 문서도 파편화되어 있고, 현대적인 프로그래밍 방식과는 결이 많이 다르죠. 하지만 Antigravity는 포기하지 않았습니다. 에이전트는 낡은 참고 자료들을 훑고, 실제 X11 이벤트를 하나하나 추적해가며 XIM 통신 로직을 현대적인 Rust 코드로 재해석했습니다. (`unim-test-xim` 구현 등)

## 바이브는 정복이 되다

DBus와 XIM이라는 두 마리 토끼를 잡았을 때, `unim`은 비로소 시스템과 한 몸이 되었습니다. 이제 어떤 앱에서든, 어떤 환경에서든 `unim`은 동일한 품질의 한글 입력을 보장하게 되었습니다.

이 성공은 저의 '바이브'와 Gemini 3 Flash의 '지능', 그리고 Antigravity의 '집요한 실행력'이 만났기에 가능한 정복이었습니다. 입력기의 세계에서 가장 넘기 힘들다던 시스템 하부의 벽을 넘은 것이죠.

## 5편을 마치며

드디어 `unim`은 기술적, 미학적, 그리고 시스템적으로 완성된 모습을 갖추게 되었습니다. 이제 남은 건 이 모든 노력이 하나의 브랜드로 완성되는 순간입니다.
