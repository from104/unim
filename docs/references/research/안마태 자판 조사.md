## 0. 한 줄 요약

**안마태 자판**은 자모 입력 순서가 바뀌어도 한 음절로 재배열해 조합하는 *모아치기(stroke-replay)* 입력 자판. 안마태 신부가 30년에 걸쳐 개발하고 2003년 KAIST 김진형 교수와 함께 공식 발표한 변종이 표준화된 유일 버전이며, libhangul `hangul-keyboard-ahn.xml.template` 으로 명세가 공개되어 있다.

음절 경계는 **(a) cho/jung/jong 영역이 한 번씩 채워졌을 때 + (b) 같은 영역 두 번째 자모 입력 시 분리**로 결정한다 (시간 기반 chord 아님 — 영역 위치로 결정적).

## 1. 변종 비교

| 항목 | 1977~80년대 원본 | 2003년 최종판 |
|---|---|---|
| 개발자 | 안마태 신부 (미국 성공회) | 안마태 신부 + KAIST 김진형 교수 |
| 발표 | 미국 내 실험 단계 | 2003년 한국 공식 발표 |
| 특징 | 30년 연구 산물 | 풀어 치기 / 모아 치기 / 동시 치기 모두 가능 |
| 매핑 자료 | 거의 부재 | libhangul XML 표준 |
| 사용자층 | 소수 (미국) | 한국 + 국제 |

**UNIM 도입 권고 변종**: **2003년 최종판**.

이유:

- 안마태 자판의 **공개 표준화된 유일 버전**.
- libhangul·날개셋·구름 등 여러 IME가 지원해 데이터 검증 가능.
- 키 배열·자모 결합 매핑이 명세화되어 있음.

## 2. 키 배열 — libhangul XML 기준

> **주의**: 아래 매핑은 1차 정리. 실제 자판 JSON 작성 전에 libhangul XML 원본을 다시 fetch해 100% 일치시킬 것: <https://github.com/libhangul/libhangul/blob/main/data/keyboards/hangul-keyboard-ahn.xml.template>

### 2.1 초성 (chosung)

| 영문 키 | Unicode | 자모 |
|---|---|---|
| f | U+1100 | ㄱ |
| e | U+1102 | ㄴ |
| d | U+1103 | ㄷ |
| r | U+1105 | ㄹ |
| q | U+1106 | ㅁ |
| a | U+1107 | ㅂ |
| w | U+1109 | ㅅ |
| s | U+110C | ㅈ |
| g | U+110B | ㅇ |
| t | U+1112 | ㅎ |

거센소리(ㅋ/ㅌ/ㅍ)·된소리(ㄲ/ㄸ/ㅃ/ㅆ/ㅉ)는 2-key 조합으로 생성.

### 2.2 중성 (joongsung)

| 영문 키 | 자모 |
|---|---|
| j | ㅏ |
| u | ㅑ |
| h | ㅓ |
| y | ㅕ |
| l | ㅗ |
| o | ㅛ |
| p | ㅜ |
| i | ㅠ |
| ; | ㅡ |
| k | ㅣ |

복모음(ㅘ/ㅙ/ㅚ/ㅝ/ㅞ/ㅟ/ㅢ)은 2~3-key 조합.

### 2.3 종성 (jongsung)

| 영문 키 | Unicode | 자모 |
|---|---|---|
| v | U+11A8 | ᆨ |
| c | U+11B8 | ᆸ |
| b | U+11BC | ᆼ |
| x | U+11AE | ᆮ |
| . | U+11AF | ᆯ |
| m | U+11AB | ᆫ |
| n | U+11BA | ᆺ |
| z | U+11BD | ᆽ |
| / | U+11C2 | ᇂ |

겹받침은 종성 키 2개 조합 (순서 무관).

### 2.4 Shift 처리

**안마태 핵심 특징**: 모든 자모가 lower (Shift 없이) 배치. upper(Shift)에는 같은 자모 또는 특수문자.

## 3. 음절 경계 알고리즘

### 3.1 영역 채움 + 같은 영역 재입력 분리

```
1. 사용자가 자모 키 입력 (영역별 분류 자동)
2. 현재 음절에 영역별 자모 누적
3. 음절 경계 트리거:
   (a) 모든 영역 채워짐 — cho ≥ 1 AND jung ≥ 1 인 상태 + 다음 키
   (b) 같은 영역 두 번째 자모 (jong은 jong_unordered=true면 2개까지 OK)
4. 트리거 시 현재 음절 force_compose, 새 음절 시작
5. 명시적 분리 키(Space)로도 강제 완성
```

### 3.2 시간 기반 chord — 미채택

안마태 자판은 시간 제약 없는 "동시 치기" 가능 = 영역 분리로 충분. 시간 기반 알고리즘은 고속 타이피스트 옵션으로만 여지.

### 3.3 종성 순서

ㄱ+ㄹ = ㄹ+ㄱ = ㄺ (순서 무관). 결합 lookup의 양방향 등록 필요.

## 4. 자모 결합 규칙

### 4.1 거센소리 (cho 조합)

- ㅋ: ㄱ + ㅎ
- ㅌ: ㄷ + ㅎ
- ㅍ: ㅂ + ㅎ
- ㅎ은 단독 키(이미 lower에 존재)

### 4.2 된소리

- ㄲ: ㄱ + ㄱ
- ㄸ: ㄷ + ㄷ
- ㅃ: ㅂ + ㅂ
- ㅆ: ㅅ + ㅅ
- ㅉ: ㅈ + ㅈ

### 4.3 복모음 (jung 조합)

- ㅔ: ㅏ + ㅣ ← 안마태는 ㅔ도 조합으로!
- ㅐ: 별도 (조합 또는 단독)
- ㅘ: ㅗ + ㅏ
- ㅙ: ㅗ + ㅏ + ㅣ (3-key)
- ㅚ: ㅗ + ㅣ
- ㅝ: ㅜ + ㅓ
- ㅞ: ㅜ + ㅓ + ㅣ
- ㅟ: ㅜ + ㅣ
- ㅢ: ㅡ + ㅣ

### 4.4 겹받침 (jong 조합, 순서 무관)

- ㄳ, ㄵ, ㄶ, ㄺ, ㄻ, ㄼ, ㄽ, ㄾ, ㄿ, ㅀ, ㅄ — 모두 종성 키 2개 chord, 어느 순서든 결합

## 5. 키별 메타 (key_meta) 적용 가능성

### 5.1 vowel_combine_head

안마태에서 `ㅗ`/`ㅜ`는 한 키에만 매핑되어 v2 룰 A(키별 head 차이)는 적용 의미 약함. **불필요 — 명시 안 함이 default**.

### 5.2 context_alt

안마태 동시 치기에서 키가 위치 기반으로 영역 결정 → 컨텍스트 분기 불필요. **명시 안 함**.

### 5.3 결론

key_meta는 안마태 첫 빌트인에서는 비워둠. 향후 사용자 변종이 필요하면 추가 가능.

## 6. JSON 구조 초안 (도입 시점 참고용)

```jsonc
{
  "schema_version": 3,
  "language": "korean",
  "name": "anmatae",
  "type": "anmatae",                          // ← 신설 layout_type
  "metadata": {
    "display_name": {
      "ko": "안마태 자판 (2003)",
      "en": "Ahnmatae Keyboard (2003)"
    },
    "author": "안마태·김진형 (2003)",
    "description": "...",
    "version": "1.0",
    "tags": ["korean", "anmatae", "moachigi", "phonetic"]
  },
  "layout": {
    "lower": {
      "1st": [...],
      "2nd": [...],
      "3nd": [...],
      "4th": [...]
    },
    "upper": { /* shift = lower와 동일 또는 특수문자 */ }
  },
  "combinations": {
    "cho": [
      {"first":"ㄱ","second":"ㅎ","result":"ㅋ"},
      {"first":"ㄷ","second":"ㅎ","result":"ㅌ"},
      {"first":"ㅂ","second":"ㅎ","result":"ㅍ"},
      {"first":"ㄱ","second":"ㄱ","result":"ㄲ"}
      // ... 된소리 5개
    ],
    "jung": [
      {"first":"ㅏ","second":"ㅣ","result":"ㅐ"},  // 또는 ㅔ
      {"first":"ㅗ","second":"ㅏ","result":"ㅘ"}
      // ... 복모음 7~9개
    ],
    "jong": [
      // 겹받침 11개 (jong_unordered=true로 양방향 자동 등록)
    ]
  },
  "moachigi": {
    "enabled": true,
    "syllable_boundary": "region_filled",       // (a)+(b) 알고리즘
    "jong_unordered": true                       // 종성 순서 자유
  }
}
```

## 9. UNIM 도입 시 영향 범위 요약

UNIM 0.2.0+의 v1·v2 schema와 두벌식·세벌식 composer 구조에서는 안마태 자판의 키 배열·자모 결합은 표현 가능하지만, **모아치기 동작 자체는 composer 코어 변경 + v3 schema 신설을 필요로 한다**. 자세한 영향 분석:

- **v2로 표현 가능**: 키 배열, 자모 결합 규칙(ordered), 키별 메타.
- **추가 필요**: 종성 영역 양방향 결합, 영역 간 순서 자유, 음절 경계 자동 결정 알고리즘.
- **신설 layout_type**: `"anmatae"` 또는 상위 카테고리 `"moachigi"`.
- **신설 schema 필드**: `moachigi: { enabled, syllable_boundary, jong_unordered }`.
- **신설 composer**: `HangulComposerAnmatae` (큐를 영역별 버퍼링 + force_compose 알고리즘).

도입 결정 시 별도 plan 작성 권장. 본 문서는 그 plan의 입력 자료로 활용.
