## 0. 한 줄 요약

- **복벌식**: 두벌·세벌 두 오토마타를 적재하고 **어절 첫 글쇠가 왼손이면 두벌식·오른손이면 세벌식**으로 어절 단위 자동 전환. 날개셋에만 존재하는 극도로 niche한 실험적 방안(표준화 안 됨).
- **갈마들이(첫가끝 갈마들이)**: 한 글쇠가 **입력 차례(첫/가/끝)에 따라 다른 낱자를 출력**. 신세벌식 P2/M 등 순수 세벌식 기법(도깨비불 없음). 3beol판 libhangul 사용자라는 더 실재하는 수요층 보유.
- 동일 목표("적은 글쇠로 모아쓰기")를 **갈마들이가 더 낮은 비용·회귀 위험으로 달성**한다.

처음에 흔히 혼동하는 점: "한 글쇠가 두벌/세벌처럼 섞여 동작한다"는 직관은 **복벌식이 아니라 갈마들이**에 해당한다. 복벌식은 글쇠를 섞는 것이 아니라 **모드를 자동 스위칭**하는 것이다.

## 1. 복벌식(複벌式)

### 1.1 정의
한글 음절은 반드시 초성으로 시작한다. 두벌식은 초성이 왼손, 공병우 계열 세벌식은 초성이 오른손에 몰려 있다. 복벌식은 두 자판 배열과 두 오토마타를 모두 적재한 뒤, **어절 첫 글쇠의 손 위치(좌=두벌, 우=세벌)로 그 어절의 벌식을 자동 판정**한다. 모드 전환키가 필요 없다.

날개셋은 "글쇠 배열"과 "한글 입력 방식(오토마타)"을 계층 분리한 구조라, 이 위에 "두벌 오토마타 + 세벌 오토마타"를 동시에 올리고 어절 첫 글쇠로 둘 중 하나를 선택하는 메타-오토마타로 복벌식을 구현한다.

### 1.2 실제 사례·수요
- 사실상 **날개셋의 "복벌식 빠른설정" 기능이 유일한 명명된 구현.**
- 위키백과: "눈에 보이는 글자가 고정적이지 않아 **복벌식 자체를 표준화하기 어렵다.**"
- 독립된 복벌식 사용자 커뮤니티는 확인되지 않음. niche 중에서도 niche.

## 2. 갈마들이(첫가끝 갈마들이)

### 2.1 정의
한 물리 글쇠에 벌이 다른 낱자 2~3개를 두고, **입력 차례(첫소리→가운뎃소리→끝소리)에 따라 어느 낱자가 나올지 결정**한다. 신세벌식 P2: 오른손 글쇠 = (초성 ∪ 중성), 왼손 글쇠 = (중성 ∪ 종성). Shift 없이 공세벌식보다 적은 글쇠로 모아쓰기가 된다. 순수 세벌식 기반이라 도깨비불이 없다.

### 2.2 실제 사례
| 자판명 | 분류 | 갈마들이 방식 |
|---|---|---|
| 신세벌식 1995 원안 / M / HS | 갈마들이 세벌식 | 한 글쇠 (초∪중) 또는 (중∪종) |
| 신세벌식 P2 (2016~18) | 갈마들이 세벌식 | 오른손=초∪중, 왼손=중∪종 |
| 갈마들이 공세벌식 3-2015 / 3-P3 / 3-D2 | 갈마들이 세벌식 | 공세벌식 + 첫가끝 갈마들이, Shift 없이 모아쓰기 |

### 2.3 다른 IME 지원
- **3beol판 libhangul**(우덜/createsc 포크)이 첫가끝 갈마들이를 처리하며, ibus-hangul과 결합해 리눅스에서 신세벌식 사용 가능 → **실재 수요층 근거**.
- 공식 libhangul·nabi·kime는 미지원.

## 3. UNIM 코드 수준 구현 가능성 비교

| 항목 | 복벌식 | 갈마들이 |
|------|--------|----------|
| 수요 | 극소수(날개셋 한정) | niche지만 실재 |
| 변경 성격 | **엔진 아키텍처 레벨** | **데이터 주도 + press_key 국소 분기** |
| 핵심 난점 | 손 판별 구조적 난점 + 가정 모호성 | `context_alt.to`가 런타임 미소비 → 자모 주입 경로 신설 |
| 예상 규모 | 신규 파일 2개 + 엔진 필드/빌드/통합, 6단계 | ~270~290 LOC, 5단계 |
| 회귀 위험 | 중~고 | 저 |

### 3.1 갈마들이 — 권고

**핵심 발견(코드 추적으로 확정):** `context_alt`의 `to` 분기는 **런타임에서 소비되지 않는다.** `src/input_engine/press_key.rs:291-303`에서 조건 충족 시 substitution 없이 정적 `keyboard_map.get(&c)`(:306)로 fall-through한다. ko_3bul390의 `"/"→ㅗ`가 동작하는 것은 layout 그리드의 정적 매핑 덕분이지 `to` 때문이 아니다. → 갈마들이는 **stage→자모를 런타임에 실제 주입하는 신규 경로**가 필요하다(따라서 ~270 LOC, 단순 50줄이 아님).

또 하나: `src/keystroke/keyboard_map.rs`의 `char_to_jamo`가 **문자 자형으로 cho/jung/jong을 자동 구분**한다(호환 자모 ㅗ→Jung, 종성 자형 ᆼ→Jong). stage별 출력 문자열에 "원하는 단계의 자형"을 쓰면 이 함수를 그대로 재사용 가능.

**스키마 확장(옵션 B):** 기존 `ContextAlt {when, to, fallback}`는 무수정하고 `KeyMeta`에 갈마 전용 필드 신설 → 회귀 0 자동 보장.
```rust
// src/keystroke/profile/schema.rs
pub struct KeyMeta {
    pub vowel_combine_head: Option<bool>,
    pub context_alt: Option<ContextAlt>,   // 기존 — 무수정
    pub galma: Option<GalmaAlt>,           // 신규
}
pub struct GalmaAlt {
    pub cho: Option<String>,   // 초성 차례 출력 (호환 자모 자형)
    pub jung: Option<String>,  // 가운뎃소리 차례
    pub jong: Option<String>,  // 끝소리 차례 (종성 자형 ᆫ ᆯ)
    pub fallback: Option<String>,
}
```
신세벌식 P2 예시(오른손=초∪중, 왼손=중∪종):
```json
"key_meta": {
  "k": { "galma": { "cho": "ㅇ", "jung": "ㅏ" } },
  "d": { "galma": { "jung": "ㅡ", "jong": "ᆫ" } },
  "f": { "galma": { "jung": "ㅓ", "jong": "ᆯ", "fallback": "f" } }
}
```

**stage 판정(기존 조건자 재사용)** — `src/hangul/input_context.rs:343-395`:
- 초성 차례 = `!is_composing()` 또는 `is_jong_filled()` → `cho`
- 가운뎃소리 차례 = `is_only_cho_filled()` → `jung`
- 끝소리 차례 = `is_cho_jung_filled()` → `jong`

**press_key 통합:** 기존 `context_alt` 블록(press_key.rs:270-303) 앞에 동일 가드로 galma 블록 추가. 주입 후 정적 `keyboard_map.get(&c)` lookup을 반드시 스킵 — 자모 처리(press_key.rs:306-424)를 공유 헬퍼로 추출해 갈마·정적 양쪽이 호출(이중 처리 방지). `produces_char_in_korean`(:698-734)에도 동일 stage 평가 추가.

**구현 순서·핵심 파일:**
1. 스키마(~30 LOC): `src/keystroke/profile/schema.rs` `GalmaAlt` + `KeyMeta.galma` + round-trip 테스트
2. 빌더 머지(~8 LOC): `src/keystroke/profile/builder.rs:253` `build_key_meta_char_map`
3. 가시성(~1 LOC): `src/keystroke/keyboard_map.rs` `char_to_jamo` → `pub(crate)`
4. 엔진(~60-80 LOC): `src/input_engine/press_key.rs` stage 평가 + 자모 주입 헬퍼 + galma 블록 2곳
5. 빌트인 JSON(자형 확정 후): `src/keystroke/keymap/ko_3bul_sin_p2.json` + 등록 3곳(`src/keystroke/mod.rs`, `src/keystroke/profile/builtin.rs`)

**리스크:** 신세벌식 P2/M 정확한 자형 매핑표 미확보(출처·라이선스 확정 후 후속 커밋으로 격리) · chord(모아치기) ON + 갈마 동시 stage 판정 꼬임(中위험) · 같은 키 `context_alt`+`galma` 우선순위(galma 우선 + 빌드 경고 권고).

### 3.2 복벌식 — 보류

- ✅ 어절 경계 감지: `src/input_engine/press_key.rs:743` `flush_preedit()`, Space 처리 :253-260
- ❌ **물리 키→손 판별 구조적 난점**: :265 `english_keymap.get_char(keycode)` 후 KeyCode 소실. 단 영문 char가 QWERTY 물리 위치 프록시 → char→손 테이블로 판별 가능(Dvorak 등은 영문 layout JSON에서 동적 빌드)
- ✅ composer 런타임 교체: `Box<dyn HangulComposer>` + `src/hangul/input_context.rs:457` `set_composer_type()`

**설계 골자:** 신규 `src/keystroke/hand.rs`(char→Hand 테이블) · schema v3 `layout_type:"bokbul"`(두 자판 이름 참조 `bokbul:{left_hand_layout, right_hand_layout}`) · 엔진 두 슬롯(`bokbul_left/right` + keymap 동반 스왑 `switch_bokbul_composer`) · 어절 첫 글쇠 고정(`bokbul_word_pending`) · 게이트 `bokbul_active` OFF 시 기존 경로 100% 보존.

**보류 이유(핵심 리스크):**
1. **어절 첫 손 = 의도한 벌식 가정이 항상 참 아님** — 세벌식390은 초/중/종이 양손에 흩어져 있어 세벌식 사용자가 왼손 자모로 어절을 시작하면 두벌식으로 오전환. 날개셋 복벌식의 본질적 한계로 설계로 완전 해결 불가.
2. 두 keymap 동시 적재로 엔진 상태 복잡도 증가 → 회귀 위험 큼.
3. 수요 극소수. 4. chord(모아치기)와 동시 활성 시 chord_buffer 꼬임 → MVP 배제 필요.

## 4. 결론·권고

1. **갈마들이를 먼저 구현**한다(ROADMAP 6단계). 데이터 주도 + press_key 국소 분기로 저위험·국소 완결, 수요층 실재.
2. **복벌식은 보류**한다. 손 판별의 본질적 모호성으로 ROI가 낮다. 6단계의 다른 항목(낱자 provenance 태깅)이 선행되면 손 판별 정확도가 개선될 수 있으므로 그 이후 재검토.
3. 갈마들이 착수 전 확인: 타깃 자판(신세벌식 P2 여부)과 정확한 자형 매핑표 출처·라이선스.
