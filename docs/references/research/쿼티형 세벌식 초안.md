# 쿼티형 세벌식 자판 초안

**세벌식 기반 · Shift 배제 · 초·중·종성 3단 조합 규칙 · 모아치기 친화 · 알파벳 26자리 포화 배치**

2026년 4월

---

## 1. 개요

쿼티형 세벌식은 QWERTY의 숫자열·기호열 관성을 최대한 유지하면서, 세벌식(초·중·종성 영역 분리) 원칙을 따르는 자판 변종이다. **Shift 동시 입력을 완전히 배제**하고, 경음·격음·겹받침·이중모음을 아랫글쇠만으로 도출한다. 경음화는 전통적인 **같은 키 연타**와 신규 **`x + ㅇ`(자음 복사)** 두 경로를 **병존**시켜 사용자가 상황(속도·모아치기·타건 안정)에 따라 선택할 수 있게 한다. 초·중·종성 각 영역에 독립적인 조합 규칙 세트를 두어 `docs/references/research/순아래받침_규칙.md`의 종성 규칙과 체계적으로 짝을 이룬다.

알파벳 26자리에 **초성 10 + 중성 6 + 종성 10 = 26자모**를 포화 배치하고, `;` `'` `,` `.` `/` 및 숫자열·기호열은 **QWERTY 기본값을 유지**한다. 세벌식의 키 영역 분리 덕분에 **모아치기**(입력 순서에 덜 민감한 조합)에 구조적으로 친화적이며, 향후 UNIM 엔진이 모아치기를 지원할 때 별도 설계 없이 자연스럽게 혜택을 본다. 특히 **종성 영역은 키 자체의 역할이 종성으로 고정**되기 때문에, 영역 내부 2키 pair 조합도 순서 무관으로 결정적이다(§6).

본 문서는 초안이며, §11의 "설계 결정 필요 사항"은 후속 검토 대상이다.

## 2. 설계 원칙

**QWERTY 관성 보존**: 숫자열(1–0)과 기호열(`-`, `=`, `[`, `]`, `\\`, `` ` ``, `;`, `'`, `,`, `.`, `/`)은 QWERTY와 동일한 자리에 둔다. 한글 모드에서는 알파벳 26자리에만 세벌식 낱자를 얹는다.

**Shift 배제**: 모든 낱자·겹받침·경음·격음·이중모음·y-glide를 아랫글쇠만으로 입력한다. Shift 동시 입력이 어려운 사용자도 접근 가능하다.

**경음화 이중 경로**: 경음(ㄲㄸㅃㅆㅉ)은 두 가지 방법으로 입력 가능.
- **연타 경로**: `ㄱ + ㄱ → ㄲ` — 전통적 IME 관습, 직관적.
- **ㅇ 복사 경로**: `ㄱ + ㅇ → ㄲ` — 빠른 타이핑·모아치기에서 시간 모호성 제거, 연타 부담 경감.

사용자는 상황에 맞게 둘 중 어느 쪽이든 쓸 수 있다. 두 경로 모두 같은 결과(ㄲ)로 수렴한다.

**세벌식 규칙 준수**: 초성·중성·종성이 **물리적으로 분리된 키 집합**을 차지한다. 도깨비불 없음, 영역 전환은 곧 새 음절 또는 다음 단계(초→중, 중→종) 진입.

**왼손 종성 · 오른손 초성**: 세벌식 관례에 따라 종성은 왼손(Q W E R A S D Z X C), 초성은 오른손(Y U I O P J K L N M)에 집중. 중성은 집게·검지 양쪽(T F G H V B)으로 분산.

**알파벳 26자리 포화 배치**: 빈 알파벳 자리 없음. 격음·경음·y-glide·겹받침은 모두 조합 경로로 해결.

**일관된 조합 표시자**: 영역 내부 조합은 표시자 키 몇 개로 통일.
- 초성: ㅎ (격음화 — 가획), ㅇ (경음화 보조 — 자음 복사)
- 중성: ㅡ (반모음화 — y-glide), ㅣ (단모음 변형 — ㅐ/ㅔ/ㅚ/ㅟ/ㅢ)
- 종성: ㅎ (격음 재해석 + 일부 격음), ㅇ (경음화 보조)

이 네 표시자(ㅎ · ㅇ · ㅡ · ㅣ)만 외우면 모든 파생 자모가 도출된다.

**모아치기 친화 — 특히 종성**: 영역 분리 덕에 중성→초성→종성이 아닌 순서로 쳐도 재조합 여지가 크다. **종성 영역은 키 자체가 초성이 될 수 없다는 구조적 불변식** 덕분에, 영역 내부 2키 pair 조합(겹받침·경음)도 순서 무관으로 결정적이다. 세부는 §6.

## 3. 배열

```text
┌─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┐
│ Q   │ W   │ E   │ R   │ T   │ Y   │ U   │ I   │ O   │ P   │
│종ㅎ │종ㄹ │종ㅅ │종ㅂ │중ㅓ │초ㄹ │초ㄷ │초ㅁ │초ㅈ │초ㅂ │
└──┬──┴──┬──┴──┬──┴──┬──┴──┬──┴──┬──┴──┬──┴──┬──┴──┬──┴──┬──┘
   │ A   │ S   │ D   │ F   │ G   │ H   │ J   │ K   │ L   │
   │종ㅇ │종ㄴ │종ㅈ │중ㅏ │중ㅡ │중ㅣ │초ㄴ │초ㅇ │초ㄱ │
   └──┬──┴──┬──┴──┬──┴──┬──┴──┬──┴──┬──┴──┬──┴──┬──┴─────┘
      │ Z   │ X   │ C   │ V   │ B   │ N   │ M   │
      │종ㅁ │종ㄱ │종ㄷ │중ㅗ │중ㅜ │초ㅅ │초ㅎ │
      └─────┴─────┴─────┴─────┴─────┴─────┴─────┘
```

**직접 배치된 낱자 (26 = 10 + 6 + 10)**:

| 영역 | 낱자 | 위치 |
|:---|:---|:---|
| 초성 (10) | ㄱ ㄴ ㄷ ㄹ ㅁ ㅂ ㅅ ㅇ ㅈ ㅎ | L · J · U · Y · I · P · N · K · O · M |
| 중성 (6) | ㅏ ㅓ ㅗ ㅜ ㅡ ㅣ | F · T · V · B · G · H |
| 종성 (10) | ㄱ ㄴ ㄷ ㄹ ㅁ ㅂ ㅅ ㅇ ㅈ ㅎ | X · S · C · W · Z · R · E · A · D · Q |

**QWERTY 유지 키 (한글 모드에서도 부호·숫자)**:
- 알파벳 잔여: `;` `'` `,` `.` `/` (5개) — 각각 `;`, `'`, `,`, `.`, `/` 그대로.
- 숫자열 전체: `` ` `` `1` `2` `3` `4` `5` `6` `7` `8` `9` `0` `-` `=` `\\` — QWERTY 동일. **세벌식 최종에서 1번에 있던 종ㅎ은 Q로 옮겨 숫자열 완전 보존**.

**손 배치 요약**:
- **왼손**: 종성 10(Q W E R A S D Z X C) + 중성 4(T F G V).
- **오른손**: 초성 10(Y U I O P J K L N M) + 중성 2(H B).

## 4. 조합 규칙

초·중·종성 각 영역에 **독립적 규칙 세트**를 둔다.

### 4.1 초성 조합

기본 초성 10개로부터 격음(ㅊㅋㅌㅍ)·경음(ㄲㄸㅃㅆㅉ)을 도출.

**격음화** (+ ㅎ, 훈민정음 가획 원리):

| 입력 | 결과 | 타수 |
|:---:|:---:|:---:|
| ㄱ + ㅎ | ㅋ | 2타 |
| ㄷ + ㅎ | ㅌ | 2타 |
| ㅂ + ㅎ | ㅍ | 2타 |
| ㅈ + ㅎ | ㅊ | 2타 |

**경음화** (두 경로 병존):

| 입력 (연타) | 입력 (ㅇ 복사) | 결과 | 타수 |
|:---:|:---:|:---:|:---:|
| ㄱ + ㄱ | ㄱ + ㅇ | ㄲ | 2타 |
| ㄷ + ㄷ | ㄷ + ㅇ | ㄸ | 2타 |
| ㅂ + ㅂ | ㅂ + ㅇ | ㅃ | 2타 |
| ㅅ + ㅅ | ㅅ + ㅇ | ㅆ | 2타 |
| ㅈ + ㅈ | ㅈ + ㅇ | ㅉ | 2타 |

연타 경로는 전통적 IME와 호환되고, ㅇ 복사 경로는 빠른 타이핑·모아치기에서 시간 모호성 없이 안정적. 사용자가 상황에 따라 선택.

### 4.2 중성 조합

기본 중성 6개(ㅏ ㅓ ㅗ ㅜ ㅡ ㅣ)로부터 단모음 변형·이중모음·y-glide를 도출한다.

**ㅡ 후행 y-glide** (반모음화):

| 입력 | 경유 상태 | 결과 | 타수 |
|:---:|:---:|:---:|:---:|
| ㅏ + ㅡ | — | ㅑ | 2타 |
| ㅓ + ㅡ | — | ㅕ | 2타 |
| ㅗ + ㅡ | — | ㅛ | 2타 |
| ㅜ + ㅡ | — | ㅠ | 2타 |
| ㅏ + ㅡ + ㅣ | ㅑ | ㅒ | 3타 (y-glide + ㅣ 결합) |
| ㅓ + ㅡ + ㅣ | ㅕ | ㅖ | 3타 (y-glide + ㅣ 결합) |

**ㅣ 후행 결합** (단모음 변형):

| 입력 | 결과 | 타수 |
|:---:|:---:|:---:|
| ㅏ + ㅣ | ㅐ | 2타 |
| ㅓ + ㅣ | ㅔ | 2타 |
| ㅗ + ㅣ | ㅚ | 2타 |
| ㅜ + ㅣ | ㅟ | 2타 |
| ㅡ + ㅣ | ㅢ | 2타 |

**ㅗ/ㅜ 결합** (ㅗ/ㅜ 기반 이중모음):

| 입력 | 경유 상태 | 결과 | 타수 |
|:---:|:---:|:---:|:---:|
| ㅗ + ㅏ | — | ㅘ | 2타 |
| ㅗ + ㅏ + ㅣ | ㅘ | ㅙ | 3타 |
| ㅜ + ㅓ | — | ㅝ | 2타 |
| ㅜ + ㅓ + ㅣ | ㅝ | ㅞ | 3타 |

*순서 의미*: ㅏ+ㅡ→ㅑ(ㅡ 후행)와 ㅏ+ㅣ→ㅐ(ㅣ 후행)는 둘째 자모로 구분되어 결정적. ㅡ+ㅣ→ㅢ(ㅣ 후행)와 ㅏ+ㅡ→ㅑ(ㅡ 후행)는 첫째 자모가 달라 충돌 없음. 중성 같은 키 연타(ㅏ+ㅏ 등)는 정의되지 않아 첫 자모 확정 + 새 음절로 처리.

### 4.3 종성 조합

기본 종성 10개(ㄱ ㄴ ㄷ ㄹ ㅁ ㅂ ㅅ ㅇ ㅈ ㅎ)로부터 겹받침·경음을 도출. **순아래받침 규칙 세트의 겹받침·격음 재해석을 상속**하고, 경음화는 초성과 같은 이중 경로(연타 · ㅇ 복사)를 제공한다.

**겹받침 2타** (모아치기 모드에서 순서 자유 — §6 참조):

| 입력 | 결과 | 비고 |
|:---:|:---:|:---|
| ㄱ + ㅅ | ㄳ | |
| ㄴ + ㅈ | ㄵ | 이 자판은 ㅈ이 직접 입력되므로 가획 경로(ㄴ+ㅅ→ㅈ) 없이도 2타로 도달 |
| ㄴ + ㅎ | ㄶ | |
| ㄹ + ㄱ | ㄺ | |
| ㄹ + ㅁ | ㄻ | |
| ㄹ + ㅂ | ㄼ | |
| ㄹ + ㅅ | ㄽ | |
| ㄹ + ㅎ | ㅀ | |
| ㅂ + ㅅ | ㅄ | |

**경음화** (두 경로 병존, 초성과 대칭):

| 입력 (연타) | 입력 (ㅇ 복사) | 결과 | 타수 |
|:---:|:---:|:---:|:---:|
| ㄱ + ㄱ | ㄱ + ㅇ | ㄲ | 2타 |
| ㅅ + ㅅ | ㅅ + ㅇ | ㅆ | 2타 |

종성 ㅇ은 A에 있으므로, 왼손 내부(X→A, E→A) 이동 2타로 경음 도달. 순아래받침 원본(연타만)과 차별화되는 **이 자판 고유 확장**.

**격음화 겹받침 (ㅎ 경유 재해석, 순아래받침 §4.5)**:

| 입력 | 경유 상태 | 결과 | 원리 |
|:---:|:---:|:---:|:---|
| ㄹ + ㅎ + ㄴ | ㅀ | ㄾ | ㅎ + ㄴ → ㄷ 재해석 |
| ㄹ + ㅎ + ㅂ | ㅀ | ㄿ | ㅎ + ㅂ → ㅍ 재해석 |

## 5. 오토마타 상태 전이 개요

세벌식 영역 분리 덕에 **영역이 달라지면 자동 음절 경계**가 생긴다(도깨비불 없음). 각 영역 내부의 상태 전이는 §4 조합 규칙을 상태 머신으로 옮긴 것이며, 순아래받침 §5와 동일한 포맷을 따른다. 상세 표는 구현 시점에 `src/hangul/` 테스트와 짝지어 확정한다.

핵심 결정적(deterministic) 보장:
- 초성 상태에서 ㅎ → 격음, ㅇ → 경음, 같은 초성 연타 → 경음. 셋 다 허용.
- 중성 상태에서 ㅡ 후행 → y-glide(ㅑ/ㅕ/ㅛ/ㅠ), ㅣ 후행 → 단모음 변형(ㅐ/ㅔ/ㅚ/ㅟ/ㅢ), ㅗ/ㅜ 선행 → 이중모음.
- ㅑ/ㅕ 경유 상태에서 ㅣ 추가 → ㅒ/ㅖ. ㅘ/ㅝ 경유 상태에서 ㅣ 추가 → ㅙ/ㅞ.
- 종성 상태에서 §4.3의 pair·경음·reinterpret 규칙. ㅀ·ㄶ에서의 ㅎ 재해석이 성립하지 않는 입력은 직전 상태 확정 후 새 음절로 흘려보낸다.

## 6. 모아치기 고려

**구조적 가능성**: 세벌식의 초·중·종성이 서로 다른 물리 키 영역에 속하므로, 사용자가 입력 순서를 바꿔도 자모 영역으로 역할을 판별할 수 있다. 어절 버퍼를 유지하고 경계 시점에 영역별 정렬 후 조합하는 **stroke-replay 오토마타**가 자연스럽게 적용 가능.

### 6.1 영역 간 순서 자유

각 키의 역할(초/중/종)은 키 위치로 결정적이므로, 사용자가 음절 안에서 **초→중→종이 아닌 순서로 쳐도 재조합 가능**.

- "한" = M(초ㅎ) + F(중ㅏ) + S(종ㄴ).
- 모아치기 모드: F + M + S, M + S + F 등 모든 순열이 "한"으로 수렴.

### 6.2 종성 영역 내부 순서 자유 (핵심)

**종성 키는 구조상 절대 초성으로 해석되지 않는다**. 따라서 종성 영역 내부에서 키 두 개가 연속 입력될 때, 그 둘은 반드시 같은 음절의 종성 pair로 묶인다. 순서가 바뀌어도 "종성 A + 종성 B"의 정렬된 집합으로 간주하면 결과는 동일하다.

- ㄹ + ㄱ → ㄺ, ㄱ + ㄹ → ㄺ (모두 `{ㄱ, ㄹ}` → ㄺ).
- ㅂ + ㅅ → ㅄ, ㅅ + ㅂ → ㅄ.
- ㄱ + ㅇ(경음) → ㄲ, ㅇ + ㄱ → ㄲ.
- ㄱ + ㄱ(연타 경음) → ㄲ (연타는 순서가 의미 없음).

이 **종성 영역의 순서 자유성**이 본 자판 모아치기 친화성의 가장 큰 이점. 중성·초성은 음절 내 역할 전환(새 음절 시작 등)이 있어 순서가 부분적으로 의미를 가지는 반면, 종성은 음절 종료 전까지 키 자체가 종성으로 확정된다.

### 6.3 순서 의존이 남는 영역

- **중성 ㅡ 후행 y-glide vs ㅣ 후행 결합**: ㅏ+ㅡ→ㅑ, ㅏ+ㅣ→ㅐ. 둘째 자모로 결정적이지만 **둘째 자모가 뭐냐**는 순서 의미를 가진다(즉 역순 ㅡ+ㅏ는 정의 외).
- **ㅗ/ㅜ 이중모음**: ㅗ+ㅏ→ㅘ. 역순 ㅏ+ㅗ는 정의 외 → ㅏ 확정 + 새 음절.
- **종성 ㅎ 재해석**: ㄹ+ㅎ+ㄴ→ㄾ. 세 자모의 순서가 중요(상태 전이 체인).

### 6.4 구현 권장 모드

- **기본**: 영역 간 자유 + 종성 영역 내부 자유(§6.2) + 중성/초성 영역 내부 순서 일부 보존(§6.3).
- **엄격 모드**: 모든 영역 순서 보존. 기존 타이핑 습관 유지 사용자용.

**UNIM 구현 현황**: v1 프로필 스키마(`docs/dev/plans/LAYOUT_PROFILE_V1.md`)는 모아치기를 지원하지 않음(§9 비목표). ROADMAP 6단계 "모아치기 (stroke replay)" 항목이 지원되는 시점에 본 자판은 별도 수정 없이 혜택을 본다.

## 7. QWERTY 유지 키

알파벳 26자리가 전부 한글 낱자에 할당되어 **빈 알파벳 자리는 없다**. 다만 다음 키들은 한글 모드에서도 **QWERTY 기본값 그대로** 작동하므로 영문 모드 전환이 불필요한 부호 입력이 가능하다.

| 구간 | 키 | 아랫글쇠 | 윗글쇠 |
|:---|:---|:---:|:---:|
| 알파벳 잔여 (5개) | `;` `'` `,` `.` `/` | `;` `'` `,` `.` `/` | `:` `"` `<` `>` `?` |
| 숫자열 (14개) | `` ` `` 1 2 3 4 5 6 7 8 9 0 `-` `=` `\\` | 각 숫자/기호 | `~` `!` `@` `#` `$` `%` `^` `&` `*` `(` `)` `_` `+` `|` |
| 기호열 | `[` `]` | `[` `]` | `{` `}` |

윗글쇠는 **한글 입력 경로에 쓰이지 않는다** — 영문 모드의 대문자·기호로만 사용. 한글 모드에서는 Shift가 완전히 잉여가 된다.

## 8. 숫자·기호 세부 (QWERTY 정렬)

한글 모드에서 알파벳 26자리만 낱자로 바뀌고, **숫자열·기호열은 QWERTY와 완전 동일**. 세벌식 최종이 숫자열 1번에 두던 종ㅎ은 본 자판에서 Q로 옮겨졌다(§3) — 그 결과 숫자열 예외가 사라지고 완전 QWERTY 호환.

**호환성 효과**:
- 숫자 입력 · 부호 입력 · 단축키(Ctrl+C 등)는 영문 모드와 한글 모드에서 **동일하게 작동**.
- 사용자는 한글 모드에서도 `1234567890-=[]\`;',./`까지 즉시 타이핑 가능.

## 9. 충돌 검증

**초/종성 경음화 · 격음화**:
- ㄱ+ㅇ→ㄲ, ㄱ+ㅎ→ㅋ, ㄱ+ㄱ→ㄲ (연타). 둘째 키로 경음/격음/연타 구분. 결정적.
- 연타와 ㅇ 복사는 같은 결과(ㄲ)로 수렴해 의미 충돌 없음.

**중성 조합 결정성**:
- ㅏ+ㅡ→ㅑ, ㅏ+ㅣ→ㅐ. 둘째 자모로 구분.
- ㅡ+ㅣ→ㅢ (ㅣ 후행). ㅡ+ㅏ는 정의 외 → ㅡ 확정.
- ㅗ+ㅏ→ㅘ, ㅗ+ㅣ→ㅚ, ㅗ+ㅡ→ㅛ. 세 방향 모두 다른 키라 결정적.
- ㅘ+ㅣ→ㅙ, ㅝ+ㅣ→ㅞ, ㅑ+ㅣ→ㅒ, ㅕ+ㅣ→ㅖ. 체인 경유도 결정적.

**중성 같은 키 연속**:
- ㅏ+ㅏ는 정의 외 → ㅏ 확정 + 새 음절 ㅏ.

**종성 영역 순서 자유**:
- ㄹ+ㄱ = ㄱ+ㄹ = ㄺ (§6.2 영역 내부 순서 자유). 모아치기 모드에서 모호성 없음.
- 엄격 모드에서는 순서 의존 유지(`ㄺ` 규칙을 pair 집합으로 해석할지 ordered tuple로 해석할지는 UNIM v1 프로필 설정으로 전환).

**ㅎ 재해석 순서 의존**:
- ㄹ+ㅎ 상태에서 ㄴ이 오면 ㅀ+ㄴ→ㄾ. 순서가 바뀌면 재해석 불성립 → 다른 경로로 분기. 상태 머신 복잡도 때문에 순서 보존.

**모아치기 모드와 엄격 모드의 명시 전환**:
- 사용자 설정(`~/.config/unim/config.yaml`)의 `korean_moachigi_mode` 같은 플래그로 전환 가능하게 설계 (v2 범위).

## 11. 설계 결정 필요 사항

1. **경음화 경로 선호도**: 연타 vs ㅇ 복사. 두 경로 병존 자체는 저비용이나, **GUI/튜토리얼에서 어느 쪽을 "기본 권장"으로 표기**할지 결정 필요. 사용자가 초기 학습 시 혼란을 줄이려면 한쪽을 명시적 "기본"으로.
2. **ㅡ 후행 y-glide의 학습성**: ㅡ를 "반모음화 표시자"로 쓰는 관습은 새로운 것. 대안: ㅏ+ㅣ=ㅐ와 ㅣ+ㅏ=ㅑ 순서 구분 방식(기존 초안 B)과 비교 타건 검증.
3. **종성 격음화 확장** (§4.3): 순아래받침 엄격 모드(가획만) vs 쿼티형 확장 모드(ㅈ+ㅎ→ㅊ, ㄷ+ㅎ→ㅌ). UNIM v1 `rule_sets`로 분리 표현.
4. **모아치기 모드 전환** (§6.4): 기본(§6.2 종성 순서 자유) vs 엄격(전 영역 순서 보존). 사용자 설정으로 전환 가능하게 할지 v1 단계에서 어느 쪽이 기본일지.
5. **ㅒ / ㅖ 3타 수용성**: ㅏ+ㅡ+ㅣ, ㅓ+ㅡ+ㅣ. 사용 빈도 낮아 3타 부담 미미하나 타건 패턴 자연스러운지 검증.
6. **ㅇ의 영역 이중 역할**: 초성 ㅇ(K)과 종성 ㅇ(A) 둘 다 "경음화 보조" 역할 겸임. 사용자가 영역 판별 헷갈리지 않게 설계·튜토리얼 필요.

## 13. 요약

**학습 자모 키**: 직접 배치 **26개** (알파벳 전부) + 조합 표시자 **4종**(ㅎ·ㅇ·ㅡ·ㅣ)로 모든 파생 자모 도출
**Shift 사용**: **0회**
**경음화 경로**: 연타 + ㅇ 복사 **2가지 병존**
**최대 타수**: **3타** (ㅙ · ㅞ · ㅒ · ㅖ · 순아래받침 재해석 종성)
**QWERTY 호환**: 숫자열·기호열 완전 일치 + `;` `'` `,` `.` `/` 유지 → 영문 모드 전환 투명
**모아치기**: 영역 분리 + **종성 영역 순서 자유(키가 초성이 될 수 없으므로 결정적)** — 엔진 지원 시 자연 적용

**핵심 특징**:
- 알파벳 26자리를 초성 10 + 중성 6 + 종성 10으로 **포화 배치**해 빈 자리 제거.
- 왼손 종성 · 오른손 초성 · 중앙 중성의 **세벌식 관례 유지**.
- 경음화에 **연타와 ㅇ 복사 두 경로 병존** — 타이핑 습관과 속도에 맞춰 선택.
- **일관된 조합 표시자 4종**(ㅎ·ㅇ·ㅡ·ㅣ)만 외우면 모든 파생 자모 도출.
- 순아래받침의 종성 규칙을 **초·중성으로 확장**한 대칭 설계 + ㅇ 복사라는 **이 자판 고유의 경음화 보조 경로** 추가.
- **종성 영역 내부 순서 자유**로 모아치기 친화성 구조적 확보.
- Shift 동시 입력이 어려운 사용자에게 **접근성 우선** 세벌식 경로 제공.
