# UNIM 0.4.1 릴리즈 노트 (한국어)

**릴리즈 날짜**: 2026-08-16
**브랜치**: develop → main

> 한 줄 요약: 페도라 계열에 빠져 있던 **rpm 패키지를 채우고**, 고정키(Sticky Keys)로 만든 조합이 가끔 듣지 않던 문제를 고쳤습니다.

0.4.0 의 뒤를 잇는 작은 수정판입니다. 새 기능은 없고, 설정 파일 형식도 바뀌지 않았습니다. 그대로 갱신하시면 됩니다.

---

## 고쳐진 것

### 1. rpm 패키지가 릴리스에 올라오지 않던 문제

0.4.0 에는 deb 11 종과 Windows MSI 만 올라갔고 **rpm 이 하나도 없었습니다.** 페도라·RHEL 계열에서는 한 줄 설치가 아예 막혀 있었다는 뜻입니다.

빌드가 두 곳에서 깨져 있었습니다.

- **`MAKEFLAGS` 누수**: `rpmbuild` 의 `%make_build` 가 `MAKEFLAGS` 에 `--` 구분자를 끼워 넣는데, 이걸 jemalloc(`tikv-jemalloc-sys`)의 빌드 스크립트가 삼키다 실패했습니다.
- **`Qt6::GuiPrivate` 미확보**: Qt 6.8 이상(페도라 43)에서는 private 모듈을 명시적으로 요청해야 타겟이 생깁니다. deb 쪽은 Qt 6.4 라 자동으로 딸려와서 이 결함이 드러나지 않았습니다.

페도라 43 에서 실제 빌드까지 마쳤습니다. 이제 아래 한 줄이 페도라 계열에서도 동작합니다.

```bash
curl -fsSL https://raw.githubusercontent.com/from104/unim/main/install.sh | bash
```

### 2. 고정키 조합이 가끔 듣지 않던 문제 (GNOME Wayland)

텍스트 입력란 안에서 `Ctrl` → `A`, `Alt` → `F` 같은 조합이 **간헐적으로 수정자 없이 전달**돼 그냥 글자가 입력됐습니다.

입력기가 키를 가로챈 뒤 되돌려 보내면, GNOME 이 고정키 래치를 다시 입히는 지점을 건너뜁니다. 되돌아온 키가 한 박자 늦게 도착하는 사이 래치가 먼저 풀리면 수정자가 사라집니다. 이제 **입력기가 소비하지 않을 키는 가로채지 않고 그대로 넘겨** 래치가 살아 있습니다.

`Shift`+`Home`, `Shift`+방향키 같은 **선택 조작도 같은 결함**이었고 함께 고쳐졌습니다.

> 한 번에 한 키만 누를 수 있는 분들에게 고정키는 편의 기능이 아니라 조합키를 쓸 수 있느냐 없느냐의 문제입니다.

## 알려진 제약

- **조합 중에 쓰는 수정자 조합**은 래치를 보장하지 못합니다. 한글을 조합하는 도중에 `Shift`+`Home` 을 누르는 경우가 해당됩니다. 이때는 확정된 글자가 먼저 앱에 들어가는 쪽을 우선했습니다 — 글자 순서가 어긋나는 편이 더 나쁘기 때문입니다. 조합을 끝낸 뒤에 쓰시면 정상 동작합니다.

## 갱신 방법

이미 설치돼 있다면 배포판 패키지 관리자로 갱신하면 됩니다.

```bash
# Debian·Ubuntu 계열
sudo apt update && sudo apt upgrade

# Fedora·RHEL 계열
sudo dnf upgrade unim
```

또는 설치 스크립트를 다시 실행하셔도 됩니다. **설정 파일(`~/.config/unim/`)은 그대로 유지**됩니다.

> GNOME 확장 변경이 포함돼 있어, 고정키 수정이 적용되려면 **로그아웃 후 다시 로그인**해야 합니다. GNOME Shell 은 세션 중에 확장 코드를 다시 읽지 않습니다.

## 남아 있는 과제

이번 판에 담기지 못한 것들입니다.

- **샌드박스 앱(Flatpak·Snap) 한글 입력**: IBus 경로에서 커밋과 연속 입력은 0.4.0 에서 살아났지만, 조합 중 글자(preedit)가 화면에 나오지 않는 문제가 남아 있습니다.
- **XIM 경로의 조합 표시 정지**: GTK 의 `im-xim` 을 쓰는 환경에서 조합이 멈추는 문제를 아직 풀지 못했습니다.
- **Windows**: 자동 영문 전환 중 합성키(`Ctrl`+`B` 등) 미동작, 신규 설치·업데이트 후 트레이 우클릭 메뉴 미표시.
