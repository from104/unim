# 3편: 신의 한 수 - 에이전트 모드와 입력기의 대폭발

단순히 그놈 확장 프로그램의 한 기능으로 머물 뻔했던 `unim`이, 어떻게 리눅스 시스템 전체를 아우르는 '진짜 한글 입력기'로 도약할 수 있었을까요? 그 이면에는 기술적 결단보다 더 드라마틱한 **'도구의 진화'**가 있었습니다.

2026년 1월 초, 저는 큰 벽에 부딪혔습니다.

```text
733989b | 2026-01-11 | refactor: restructure project and move core logic to root crate
```

## "이걸 혼자서 다 고치라고?"

당시 `unim`은 엔진 따로, 확장 프로그램 따로, CLI 따로 노는 파편화된 구조였습니다. 진정한 입력기가 되려면 이 모든 것을 하나로 묶는 거대한 리팩토링이 필요했습니다. 하지만 수천 줄의 코드를 수정하고, 수십 개의 파일 경로를 맞추고, 각 환경(GTK, Qt, GNOME)에 맞는 인터페이스를 일일이 짜는 일은 젓가락 타이핑을 하는 저에게는 물리적으로 불가능에 가까운 도전이었습니다.

## 에이전트 모드의 등장: 개발의 패러다임이 바뀌다

마침 그때, **에이전트 모드(Antigravity/Cursor Agent)**가 제 개발 환경에 들어왔습니다. 이전까지의 AI가 단순히 "이 코드 짜줘" 수준이었다면, 에이전트 모드는 스스로 파일을 읽고, 의존성을 파악하고, 수십 개의 파일을 넘나들며 **'스스로 생각하고 실행'**하는 존재였습니다.

이건 혁명이었습니다.

- **대담한 리팩토링**: 제가 "전체 구조를 하이브리드 아키텍처로 바꾸고 싶어"라고 바이브(Vibe)만 던지면, 에이전트는 수백 개의 파일을 분석해 프로젝트 구조를 통째로 갈아엎었습니다. (`restructure project` 커밋의 정체)
- **복잡성의 정복**: 그놈 확장 프로그램(JS)과 Rust 엔진 사이의 통신 규약을 설계하고, 이를 C API와 DBus 레이어까지 일사천리로 구현해냈습니다.

## "나보다 내 코드를 더 잘 아는 파트너"

에이전트 모드는 단순한 도구가 아니었습니다. 제가 생각만 하고 실행하지 못했던 그 수많은 고민들을 실시간으로 구현해주는 **'공동 개발자'**였습니다.

혼자였다면 몇 달이 걸렸을, 아니 어쩌면 중간에 포기했을 시스템 통합 작업이 단 며칠 만에 이루어졌습니다. `unim-cli`가 샌드박스를 넘어 시스템 전반에 영향을 미치는 '진짜 입력기'로 폭발적으로 성장한 순간이었습니다.

## 3편을 마치며

에이전트 모드의 도움으로 `unim`은 이제 무서울 게 없는 강력한 뼈대를 갖게 되었습니다. 이제 이 강력한 힘을 바탕으로, 사용자들에게 보여줄 마지막 관문인 '미학적 완성'을 향해 갈 때가 되었습니다.
